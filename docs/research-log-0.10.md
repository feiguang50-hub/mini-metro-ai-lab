# 0.10 Research Closeout · Heuristic Generation

这份记录收束 0.10 之前的启发式算法实验。目的不是宣布“启发式已经完美”，而是明确什么时候继续微调的边际收益已经低于进入搜索型规划的价值。

## 结论

- 默认算法继续为 `greedy-v1`。
- `greedy-v1-1-pressure` 保留为可运行 `archived` 算法，不再调参。
- `balanced-greedy-v2` / `balanced-greedy-v2-1` 继续保留研究价值，但都没有资格替换 V1。
- geometry-only 2-opt V2.2 实验被证伪，不进入 `main`。
- heuristic generation 在 0.10 冻结。下一主线转向 Beam Search / MPC，并要求任何 rollout 都避免未来 RNG 泄漏。

## V2.2 · Geometry-only 2-opt

PR #12 使用一组在结果出现前固定的新开发 Seeds：

`1907374266, 805162878, 657531977, 978077348, 1255654432`

第一版只要几何长度有正收益就执行 2-opt relayout：Stress 从 V2.1 的 78.0 提升到 79.6，但平均候车、最长等待、高危持续与 invalid rate 略恶化。诊断证明 relayout 本身都被引擎接受，因此问题不是动作合法性，而是“更短线路”不等价于“更好客流服务”。

随后对齐 pinned upstream 的大样本证据：至少 5 站、完整 2-opt 到局部最优、总路线节省超过 20% 才重排。结果在本项目开发集上 0 次触发，V2.2 与 V2.1 完全一致。

上游 scripted heuristic 主要只能把新站接到线路头/尾，因此会积累显著 route-order debt；本项目 V1/V2 从一开始就能通过 `replace_path` 将新站插入线路任意位置。这解释了为什么上游 2-opt 的巨大收益不能机械迁移到本项目。

**状态：实验归档，PR #12 关闭未合并。**

## V1.1 · Pressure Rescue

PR #13 把候车年龄救火从 V2 topology 解耦出来，叠加到更稳的 Greedy V1 topology。等待年龄只通过公开 observation 的 passenger ID、station ID 与 `time_ms` 重建，不读取引擎私有 `wait_ms`。

### 第一版诊断

5-Seed Stress 开发集：

- V1：83.0
- V1.1：83.2
- paired：1 胜 / 1 负 / 3 平

行为探针发现一个明确机制错误：单个乘客到达 25 秒 warning 后，V1.1 可以连续多个 tick 把 2 节车厢与 3 辆机车全部投入同一条线。正收益 Seed 与负收益 Seed 都存在相同资源倾倒，因此这不是可靠救火策略，而是过度反应。

### 唯一一次机制级修正

冻结以下规则，不再通过 qualification 反向调参：

- 25 秒 warning 年龄 alone 不触发资源投入；
- 队列规模仍可触发非临界救火；
- 30 秒 critical 可因年龄 alone 增派一次机车；
- 同一个连续 pressure episode 最多追加一次 rescue；
- 压力解除后才重新 armed。

修正后的同一开发集：

| --- | ---: | ---: |
| Classic 平均运送 | 39.2 | 39.2 |
| Stress 平均运送 | 83.0 | **85.8** |
| Stress 平均候车 | 1.98 | **1.88** |

paired 为 1 胜 / 0 负 / 4 平。唯一分叉的正收益局只发生一次 30 秒临界机车增派。

## 为什么现在停止 heuristic 微调

连续几代结果已经说明：

1. V1 是非常强的低复杂度基线，局部规则上的小改动很容易只改变少数双峰生存局；
2. V2/V2.1/V1.1 都能改善某些健康指标，却无法在独立 qualification 上稳定扩大 deliveries；
3. 继续调整 25s/30s、队列阈值或小权重会越来越接近对开发集做参数盆栽；
4. pinned upstream 的实验同样显示，少数关键决策承载了大部分 episode 价值，单纯提高局部启发式复杂度未必解决长期决策问题。

因此下一阶段不继续制造 `V1.2/V2.3`，而是进入**显式前瞻规划**。

## 下一阶段研究约束

Beam / MPC / MCTS 必须满足：

- 不偷读真实环境未来 RNG；
- 不把复制真实 RNG 状态后的 rollout 当成公平预测，因为那等于预知未来；
- 搜索使用的状态、候选动作与评价函数必须可审计；
- 先建立安全的 rollout / clone 边界，再谈搜索深度；
- 小开发集用于机制诊断，真正晋级仍需新冻结 qualification。

0.10 的意义不是“算法研究结束”，而是**启发式这一代完成收敛，研究主线升到下一层抽象。**
