# 🧬 Algorithm History / 算法进化史

这个文件记录 Mini Metro AI Lab 中**所有进入正式实验的算法**，包括最终冠军、阶段性冠军、失败方案和被淘汰方案。

目标不是只留下“最后赢的人”，而是保留完整的工程与研究记忆，避免未来重复走已经验证过的死路，也方便理解冠军策略是怎样一步步演化出来的。

## 记录原则

每个进入 Arena 的算法都必须留下以下信息：

- 算法名称与版本
- 实现提交 / PR
- 核心思路
- 关键参数
- 对战基线
- 固定 Seeds 与模拟预算
- Simulation Protocol 版本
- Benchmark Scenario 版本
- 平均运送量
- 中位数
- 最低 / 最高运送量
- Game Over 率
- 候车与拥堵健康指标
- 无效动作数量 / 比例
- 主要优点
- 主要缺点
- 失败案例 / 典型崩局模式
- 最终状态
- 淘汰原因或晋级原因
- 是否值得未来复活

## 状态定义

| 状态 | 含义 |
| --- | --- |
| `baseline` | 当前基准算法 |
| `candidate` | 正在实验或调参 |
| `champion` | 当前默认冠军 |
| `retired` | 曾经有效，但已被更强方案替代 |
| `eliminated` | 经公平对战后淘汰 |
| `archived` | 保留研究价值，但暂不继续投入 |

## 实验纪律

1. **不删除失败算法的历史。** 代码可以移出默认路径，但实验记录必须保留。
2. **不只记录分数。** 还要写清楚它为什么赢、为什么输，以及在哪类局面下会崩。
3. **同一轮比较必须使用相同 Seeds、步长、时间预算、场景和 Simulation Protocol。**
4. **任何“新冠军”必须在 Arena 中明确击败当前冠军。**
5. **小样本结果只算候选证据。** 真正晋级前要扩大 Seeds 数量，并观察最差局表现。
6. **被淘汰不等于没价值。** 某些算法可能适合作为搜索启发、局部策略、Value 特征或应急控制器。
7. **协议升级不改写历史。** 旧结果保留原协议标签；需要新口径时重新跑并追加记录。
8. **场景升级也不偷换赛道。** Classic、Stress、Boss 等场景必须显式版本化，禁止把不同压力分布的成绩直接拼成同一排行榜。

## Simulation Protocol 版本

### Protocol V1 · 0.6.x 及以前

上游引擎在结构化动作被拒绝时不会推进模拟时间，而旧 Arena / CLI Battle 直接进入下一次 planner round。因此出现无效动作的局可能比名义预算少经历少量城市时间，例如 15 分钟实验实际结束于 14.98 分钟。

这不会让旧结果“失效”，但意味着它们只能与同样使用 Protocol V1 的实验直接比较。

### Protocol V2 · 0.7.0 起

拒绝的 planner 动作仍记录为 invalid，但该轮随后以 `noop` 消耗同一个固定 `dt`。除非 Game Over，算法每一轮都承担完全相同的城市时间，因此固定预算不再被无效动作悄悄缩短。

Protocol V2 同时引入时间加权网络健康指标。0.8.0 起又补齐与引擎失败条件一致的 Passenger Pressure：按等待最久的一组乘客相对最大等待时间计算风险，并记录峰值风险、最长等待与高危持续时间。

# 实验记录

## Greedy Planner V1

- **ID**：`greedy-v1`
- **状态**：`baseline`
- **首次进入仓库**：0.1.x
- **核心思路**：
  - 开局按几何距离建立短线路骨架；
  - 新站以最小额外绕行代价插入已有线路；
  - 空线路优先分配机车；
  - 高压力线路优先增加机车与车厢；
  - 通过拓扑冷却避免频繁重画线路。
- **优点**：透明、稳定、计算成本低、容易复现和调试。
- **缺点**：明显短视，只优化局部几何代价和即时拥堵；缺少站型稀缺性、换乘价值、线路均衡和未来客流预测。
- **当前作用**：作为所有后续算法的第一基线。
- **淘汰条件**：新算法在扩大后的固定 Seed 集上稳定提高均值，同时不能显著恶化最差局和 Game Over 率。

## Balanced Greedy V2 · 首次挑战

- **ID**：`balanced-greedy-v2`
- **版本**：`2.0-candidate`
- **状态**：`candidate`
- **实现 PR**：#5
- **对战基线**：`greedy-v1`
- **核心思路**：
  - 开局不仅考虑距离，还优先覆盖不同站型；
  - 新站插入评分同时考虑额外绕行、线路长度、线路客流压力和站型多样性；
  - 当已有线路过长且仍有可用线路槽位时，允许另开分流线路；
  - 机车和车厢扩容从固定绝对阈值改为结合网络平均压力的相对判断；
  - 拓扑调整冷却从 700 ms 提高到 900 ms，减少频繁改线。

### Classic V1 · Protocol V1

固定 Seeds `42, 314, 2026, 4096, 65537`，100 ms 步长，15 分钟名义预算：

| Seed | Greedy V1 | Balanced V2 | 差值 |
| ---: | ---: | ---: | ---: |
| 42 | 38 | 38 | 0 |
| 314 | 42 | 42 | 0 |
| 2026 | 42 | 42 | 0 |
| 4096 | 35 | 35 | 0 |
| 65537 | 35 | 37 | +2 |

V2 平均 38.80，V1 平均 38.40。优势约 1%，不足以晋升。

### Classic V1 · Protocol V2

在 PR #8 / 0.7.0 中重新跑相同 Seeds 和预算。所有未 Game Over episode 都精确运行到 15.00 分钟。

| 指标 | Greedy V1 | Balanced V2 |
| --- | ---: | ---: |
| 平均运送量 | 38.40 | **38.80** |
| deliveries / min | 2.56 | **2.59** |
| 时间加权平均候车人数 | 0.37 | **0.35** |
| 平均 Peak Risk | 28.2% | 28.2% |
| 平均最长等待 | 22.2s | **20.9s** |
| Game Over 率 | 0% | 0% |
| invalid action rate | 55.3% | **48.5%** |

Classic 证明 V2 没有明显回退，但也显示这个赛道太温和，无法检验持续扩张下的救火能力。

## Stress V1 · 首次高压挑战

- **Scenario**：`stress-v1`
- **Simulation Protocol**：`V2`
- **固定 Seeds**：`42, 314, 2026, 4096, 65537`
- **步长**：100 ms
- **预算**：15 分钟
- **规则**：固定 Seed 站点池，开局初始站，此后每 45 秒模拟时间开放一个新站直到上限。

### 逐 Seed

| Seed | V1 运送 | V2 运送 | V1 时间 | V2 时间 | V1 Peak Risk | V2 Peak Risk |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 42 | **129** | 94 | **15.00m** | 12.63m | 55% | 100% |
| 314 | 57 | **71** | 9.05m | **10.11m** | 100% | 100% |
| 2026 | **104** | 55 | **13.10m** | 9.35m | 100% | 100% |
| 4096 | **129** | 101 | **15.00m** | 13.15m | 94% | 100% |
| 65537 | 50 | **66** | 8.82m | **10.30m** | 100% | 100% |

### 汇总

| 指标 | Greedy V1 | Balanced V2 |
| --- | ---: | ---: |
| 平均运送量 | **93.80** | 77.40 |
| deliveries / min | **7.42** | 6.89 |
| 时间加权平均候车 | **1.75** | 2.14 |
| 平均 Peak Risk | **89.8%** | 100.0% |
| 平均最长等待 | **48.2s** | 57.1s |
| 平均高危持续 | **18.1s** | 44.2s |
| Game Over 率 | **60%** | 100% |
| invalid action rate | 40.6% | 40.9% |

### Stress V1 结论

1. **Stress V1 成功拉开了算法差异。** V1 平均运送比 V2 高约 21.2%，并且 5 个 Seed 中有两个活满 15 分钟；V2 全部 Game Over。
2. **V2 的 Classic 微弱优势不能外推到高压环境。** 它在低压时更均衡，但持续扩张后平均候车、更长等待和高危持续时间都明显恶化。
3. **Passenger Pressure 与引擎失败机制对齐。** 所有 Game Over episode 的 Peak Risk 均达到 100%；未 Game Over 的 V1 Seed 4096 最高达到 94%，说明它曾进入临界区但成功避免第二个超时乘客同时形成失败条件。
4. **V2 暂不淘汰。** 这次失败给出了明确可修方向：高压时要更积极地集中运力、保留应急资源、减少平均主义式分流，并直接面向等待时间而不是只看线路总压力。
5. **下一候选是 Balanced Greedy V2.1。** 它必须在 Classic 不显著退化的同时，优先改善 Stress 生存率和高危持续时间；否则不进入下一阶段搜索算法。

**Balanced V2 当前状态：继续作为 `candidate`，但已确认存在高压失败模式。**

> 历史记录只追加和修正事实，不因算法被淘汰而删除。
