# 🧬 Algorithm History / 算法进化史

这个文件记录 Mini Metro AI Lab 中**所有进入正式实验的算法**，包括最终冠军、阶段性冠军、失败方案和被淘汰方案。

目标不是只留下“最后赢的人”，而是保留完整的工程与研究记忆，避免未来重复走已经验证过的死路，也方便理解冠军策略是怎样一步步演化出来的。

## 记录原则

每个进入 Arena 的算法都必须留下以下信息：

- 算法名称与版本
- 实现提交 / PR
- 核心思路
- 关键参数
- 对战基线
- 固定 Seeds 与模拟预算
- 平均运送量
- 中位数
- 最低 / 最高运送量
- Game Over 率
- 无效动作数量
- 主要优点
- 主要缺点
- 失败案例 / 典型崩局模式
- 最终状态
- 淘汰原因或晋级原因
- 是否值得未来复活

## 状态定义

| 状态 | 含义 |
| --- | --- |
| `baseline` | 当前基准算法 |
| `candidate` | 正在实验或调参 |
| `champion` | 当前默认冠军 |
| `retired` | 曾经有效，但已被更强方案替代 |
| `eliminated` | 经公平对战后淘汰 |
| `archived` | 保留研究价值，但暂不继续投入 |

## 实验纪律

1. **不删除失败算法的历史。** 代码可以移出默认路径，但实验记录必须保留。
2. **不只记录分数。** 还要写清楚它为什么赢、为什么输，以及在哪类局面下会崩。
3. **同一轮比较必须使用相同 Seeds、步长和时间预算。**
4. **任何“新冠军”必须在 Arena 中明确击败当前冠军。**
5. **小样本结果只算候选证据。** 真正晋级前要扩大 Seeds 数量，并观察最差局表现。
6. **被淘汰不等于没价值。** 某些算法可能适合作为搜索启发、局部策略、Value 特征或应急控制器。

# 实验记录

## Greedy Planner V1

- **ID**：`greedy-v1`
- **状态**：`baseline`
- **首次进入仓库**：0.1.x
- **核心思路**：
  - 开局按几何距离建立短线路骨架；
  - 新站以最小额外绕行代价插入已有线路；
  - 空线路优先分配机车；
  - 高压力线路优先增加机车与车厢；
  - 通过拓扑冷却避免频繁重画线路。
- **优点**：透明、稳定、计算成本低、容易复现和调试。
- **缺点**：明显短视，只优化局部几何代价和即时拥堵；缺少站型稀缺性、换乘价值、线路均衡和未来客流预测。
- **当前作用**：作为所有后续算法的第一基线。
- **淘汰条件**：新算法在扩大后的固定 Seed 集上稳定提高均值，同时不能显著恶化最差局和 Game Over 率。

> Arena 基础设施建立之后，所有后续算法的正式对战结果都会继续追加到本文件。历史记录只追加和修正事实，不因算法被淘汰而删除。
